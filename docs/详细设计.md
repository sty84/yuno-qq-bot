# YUNO 2.0 详细设计（按需求确认 · 2026-08-06）

## 1. 需求确认摘要

| 问题 | 决定 |
|---|---|
| 前端使用者 | 单管理员管理内容；公开展示页给所有人看 |
| 展示形态 | GitHub 风格：图表统计 + 技术文档；管理区需密码进入 |
| 高危操作 | 未来移动管理 App + Web 管理区，均需密码/二次确认 |
| 任务进度 | 2 秒轮询即可，不需要 WebSocket 推送 |
| AI 模型 | DeepSeek 直连（Hermes 也用 DeepSeek） |
| Hermes 位置 | 云端服务器（4 核 4G，40G 盘） |
| QQ 前台 | 保持自研 bot.py（Hermes 网关无人设/游戏/场景记忆） |
| MCP | 先接腾讯云；第三方以后扩展 |
| 本地工具缺口 | 补：日志检索、远程命令（白名单） |
| 多模态 | 保留接口，功能先不做 |
| 传感器 | 5 个、30 秒一条、考虑冗余 |
| 扩展场景 | 未来养鱼监测：水质传感器 + 摄像头 + 设备控制 |
| 向量库 | 10G+，文档原文+向量存 NAS |
| 数据库 | SQLite（不引入 PostgreSQL） |
| NAS | J1900（弱 CPU，轻量用途） |
| GPU | 台式机 2060S，负责知识库向量化 |
| 唤醒确认 | 云端确认一次即可 |

## 2. 关键技术决策

### 2.1 NAS J1900 的边界

J1900 是 4 核低功耗 CPU，跑 Docker 可以，但**不能干重活**：

- 传感器采集/聚合/上报：✅ 轻量，没问题；
- 文档向量**存储与检索**：✅ 用磁盘型量化索引（sqlite-vec / LanceDB）；
- 文档**向量化计算（embedding）**：❌ 交给台式机 2060S 批量算；
- 大模型/重数据库：❌ 不跑。

### 2.2 向量库 10G+ 方案

```
文档 → NAS 本地存储（原文 + 向量）
  → 台式机 2060S 批量向量化（GPU 加速）
  → NAS 建量化索引（内存放不下，走磁盘型 ANN）
云端：只存元数据（文档名/路径/向量数/更新时间），按需检索
检索链路：Hermes/前端 → 网关 → 本地 MCP vector.search
  → 设备隧道 → NAS 检索 → 返回命中片段（大文件不出 NAS）
```

### 2.3 传感器冗余

- 5 个传感器按“组”配置（如 3+1 冗余），同组读数**聚合去抖**（去离群值取中位/均值）；
- 每个传感器带心跳与健康状态，坏了不影响整组数据连续；
- 协议层抽象：首选 MQTT，Modbus/串口/HTTP 留适配口（传感器项目还没实践，
  先按可插拔设计）。

### 2.4 远程命令（安全设计）

远程命令只走白名单，不开放任意 shell：

```json
{
  "keyword": "nas",
  "type": "process",
  "allow_commands": ["df -h", "systemctl status *"]
}
```

实现：`qqbot-ctl exec <keyword> <command>`，root 脚本校验命令是否匹配
该服务的 `allow_commands` 模式，全部写审计。MCP 工具 `remote.run` 调用它。

### 2.5 日志检索

`logs.search(service, pattern, lines=200)`：`qqbot-ctl <kw> logs [grep]`，
docker 走 `docker compose logs | grep`，systemd 走 `journalctl -u`，全部过
白名单脚本 + 审计。

## 3. 分层模块设计

### 3.1 用户层

**客户端矩阵（共用同一网关契约）**：

| 客户端 | 形态 | 说明 |
|---|---|---|
| 公开展示页 | Web（GitHub 风格，无需登录） | 图表统计、技术文档 |
| Web 管理区 | 密码 + Token | 服务/设备/审计/高危操作 |
| 移动管理 App（未来） | 复用 `/api/v1` | 高危操作确认、告警推送 |

**公开展示页**：
- 图表统计：服务健康、传感器遥测曲线、设备在线状态；
- 技术文档：企划/部署/详细设计/使用说明（Markdown 渲染）。

**管理区**（密码 + Token 登录，单管理员；Web 与未来 App 共用）：
- 服务管理、设备/传感器、向量库、审计、告警；
- 高危操作（停服务/重启/清记忆/远程命令/唤醒）→ 二次确认。

### 3.2 接入层

- **nginx**：域名 + Let's Encrypt HTTPS、限流、CORS；
- **API Gateway**（FastAPI，`yuno-api.service`）：
  - `/api/v1/auth`：登录/Token/改密；
  - `/api/v1/data/*`：只读数据接口（服务/遥测/审计/向量元数据）；
  - `/api/v1/agent/*`：Hermes 代理（熔断降级到 DeepSeek）；
  - `/api/v1/tasks/*`：长任务队列（task_id + 2s 轮询状态）。

**为未来移动 App 预留的设计**：
- API 契约版本化 `/api/v1` + OpenAPI 自动文档：App 只依赖契约，后端演进不影响；
- 鉴权：短期 Bearer Token + refresh，App 可安全存储；
- **确认流**：高危操作生成确认请求 ID（tasks/wake_requests 表），
  Web 与 App 均可确认，未来可扩展 QQ 确认；
- **主动推送**：现阶段 App 用 2s 轮询 + QQ 播报兜底；
  预留 FCM / APNs / 极光等推送通道，告警与确认请求可即时到达手机。

### 3.3 AI 层

- **Agent 编排（新）**：本仓库新增 `agent/` 包，`agent.ask` 统一入口：
  意图/状态分析 → Memory 融合检索（用户记忆 + 事件图/事件树）→
  `persona.compose`（persona.md 人设 + 心情 + ai_memory 经历/观点）→
  云端 LLM（DeepSeek）→ 回复后由 `memory.ingest` 反馈学习；
  `agent.grow()` 定期巩固 AI 观点、修剪低价值记忆，形成成长闭环；
- Hermes Agent（`hermes.service`，aiagent，DeepSeek 直连：
  OpenAI 兼容 `base_url=https://api.deepseek.com`）；
- Hermes API 只监听 127.0.0.1:8642，仅网关可访问；
- MCP Client 接：本地 MCP（必选）、腾讯云 MCP（先接）。

### 3.5 数据层（SQLite 表）

| 表 | 内容 | 保留策略 |
|---|---|---|
| memories（统一记忆：scope/key/fact/embedding） | QQ 与 Hermes 共用，向量化就绪 | 长期 |
| kv / bindings / scores / nicknames / state | 群计数/身份/分数/状态 | 长期 |
| audit | 操作审计 | 5000 条滚动 |
| notifications | 播报队列 | 发送后保留 7 天 |
| devices | NAS/GPU 在线状态 | 长期 |
| telemetry | 传感器数据（site/group + 指标） | 90 天，按天归档 |
| tasks / wake_requests | 任务与唤醒确认 | 30 天 |
| vector_meta | 向量库元数据（云端） | 长期 |
| alert_rules | 指标阈值告警规则 | 长期 |

每日备份：`tools.py backup`（SQLite 在线备份到 `data/backups/`，保留 7 份，
cron 每天 03:00 执行）。

### 3.6 边缘层

- **ws_server.py**（`yuno-ws.service`）：反向 WebSocket 多消息通道
  （telemetry / vector-query / task-control / wake），设备注册制 + 命令持久化；
- **nas_agent**（Docker 跑在 J1900）：MQTT 采集、聚合去抖、5 分钟批量上报、
  断网补传、磁盘向量索引、WoL 唤醒（白名单）；
- **gpu_agent**（台式机 2060S，开机自启）：接收向量化/推理任务，
  5~10s 上报进度，跑完回传；
- 唤醒流：云端发起 → 你确认一次 → NAS 发魔包。

### 3.7 运维层

- 全服务 `User=aiagent`，systemd：qqbot / hermes / yuno-api / yuno-ws / yuno-web；
- 全部登记进 services 注册表（含 hermes、yuno-api、yuno-ws、yuno-web）；
- 健康检查**独立进程**（`tools.py health` + cron，不依赖 bot）：
  状态变化（在线↔离线）经 `notify.send` 播报去重；
  `/healthz` 探活随 API Gateway（M4）落地；
- 每日备份 `tools.py backup`（保留 7 份）；
- 一键恢复 `tools.py recover --notify`。

### 3.8 扩展场景：养鱼监测（未来，复用同一套设备通道）

**站点模型**：数据从第一天就带 `site`/`group` 字段，
环境监测是一组、鱼缸是另一组，互不干扰：

```
site: 鱼缸
  ├── 水质组：水温 / pH / 溶解氧 / 电导率 / 氨氮 / 浊度 / 水位 / 流量
  └── 设备组：增氧泵 / 加热棒 / 过滤 / 喂食器（执行器）
```

**新增能力**（在现有通道上扩展，不动架构）：

| 能力 | 实现 |
|---|---|
| 水质采集 | NAS 经 MQTT 收水质传感器（复用采集/聚合/批量上报管道） |
| 执行器控制 | 增氧/加热/喂食开关：白名单 + 二次确认 + 定时（cron），写审计 |
| 鱼行为视觉 | 水下/缸顶摄像头 → 2060S 跑鱼行为分析（异常/摄食/计数），走 GPU 任务 |
| 告警规则 | `alert_rules` 表：每指标阈值（如水温 24~28℃、溶解氧下限）→ `notify.send` → QQ/未来 App |
| 展示 | 鱼缸遥测曲线、告警时间线进公开展示页 |

**复用清单**：NAS 采集管道、设备隧道、批量上报/断网补传、
GPU 任务调度、告警→QQ 播报、前端图表——全部现成，养鱼场景只新增
“执行器控制”和“告警规则”两个小模块。

### 3.9 统一记忆库（QQ bot 与 Hermes 共用）

**原则**：QQ bot 与 Hermes（或未来其他 Agent）共用一套记忆，
“从始至终是同一个人”。统一存 SQLite `memories` 表：

```
memories(scope, key, fact, embedding, updated_at)
  ├── admin            ← Hermes 管理端
  ├── c2c:<uid>        ← QQ 私聊用户
  ├── group:<gid>      ← QQ 群成员（key=成员ID）
  └── group_all:<gid>  ← QQ 群整体
```

Memory Core 新增表（同一 bot.db，实现集中在 `memory/` 包）：

```
events(id, scope, key, etype, title, content, importance, ts, embedding, updated_at)
  事件节点：事实归类成事件（职业规划/学习/项目/偏好/经历…）
event_relations(src, dst, rel, weight)
  事件关系边（影响 / 相关），构成事件图
ai_memory(kind, content, importance, embedding, updated_at)
  AI 自身记忆：identity / experience / belief
memory_meta(scope, key, fact, access_count, last_access, importance)
  Memory Policy 元数据：调用计数、重要度、时效
```

- **单 QQ bot 场景**：照常记录，行为不变（自动提取/查看/清除）；
- **提取成本控制**：群整体记忆每 8 条且**每小时至多提取一次**；
  成员/私聊记忆 10 分钟节流；
- **向量化 / Memory Core**：`embedding` 列 + 可插拔 provider；`tools.py memory-embed`
  回填存量向量并顺带补建事件图、巩固 AI 观点、修剪低价值记忆；开启 `memory.core`
  后 QQ 聊天按融合评分注入上下文（关键词 + 向量 + 事件图邻居 + 重要度/时效策略，
  查询节流 + 失败自动降级）；实现集中在 `memory/` 包（替代原 `rag/`）；
- **Agent 接入**：MCP 工具 `memory.search / add / clear`，
  Hermes 通过它们读写同一张表，AGENTS.md 已写清场景规则；
- **清理/备份统一**：`memory.clear` 按场景删，`tools.py backup` 一个库全带走。

**播报校验**：`config.json → notify.allow_targets` 白名单（空=不限制）；
发送失败重试 3 次后标记失败，不再堵队列。
