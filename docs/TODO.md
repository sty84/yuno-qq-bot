# 未完成事项 / 待办清单

> 持续更新。已完成的事项会移到“已完成”或直接删除。

## 高优先级

- [ ] Web 权限从“写操作=admin”细化到接口级权限
  - 例如：只读用户可看评测，但不能跑任务；管理员才能清库/导入/播报
- [ ] 类型检查接入 `mypy` 或 `pyright`
- [ ] 逐步放开更多 ruff 规则
  - 当前忽略了 `E402` / `E741` / `F841` / `F811` / `E702`
  - 后续分批修复后移除 ignore
- [ ] PG 连接池参数可配置化
  - 当前固定 `1~8`，建议支持环境变量
- [ ] PG 故障自动告警 / 降级策略
  - 目前 health 会检测 PG，但还没有自动切换或自动通知闭环

## 中优先级

- [ ] 多租户 / 多 NPC 真正逻辑
  - 已有 `scope_meta` 表，但还没有注册/权限/隔离/管理界面
- [ ] 全文检索进一步优化
  - 当前 `ILIKE + pg_trgm`
  - 数据量大后可评估 `pg_bigm` 或 PostgreSQL 原生全文检索
- [ ] 文档全面同步
  - README、迁移文档、部署文档需要与新架构完全对齐
- [ ] Docker / docker-compose 部署
  - 提供 app + PostgreSQL 一键启动
- [ ] Web 端用户级数据导出/删除入口
  - 底层有 `data-export` / `memory-clear-user`，但 Web 管理端还没有完整页面
- [ ] 备份恢复自动化
  - 已支持 `pg_dump` / `pg_restore`，但还没有定时恢复演练
- [ ] 内部 SQLite 数据保留策略
  - 已有 `internal-db-prune`，但还没接入自动清理的监控/告警

## 低优先级 / 长期

- [ ] 代码拆分
  - `plugins/_db.py`、`plugins/_db_pg.py`、`tools.py` 仍然偏大
- [ ] 多租户 / PostgreSQL 分区
  - 如果未来数据量极大，考虑按 scope 分区
- [ ] 模型蒸馏 / 本地小模型替换 LLM
  - 情绪、提取、重排等高频路径
- [ ] 可观测性完善
  - 结构化日志、指标、trace
- [ ] 公网部署安全加固
  - TLS、防火墙、限流策略、密钥管理
