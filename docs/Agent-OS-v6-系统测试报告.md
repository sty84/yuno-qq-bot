# 1. 长期记忆类型区分

**测试方案**：分别写入事实、事件、推理、信念、玩笑五类内容，检查存储落点与生命周期差异。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| 用户说"我养了一只橘猫" | 存为 Fact（memories） | ✅ `ingest:*` 落 memories，带 confidence/source |
| 用户完成项目 | 存为 Event（events+关系边） | ✅ events 表 + related_to/follows 边 + 来源记忆追踪 |
| 决策咨询结论"用户倾向 X" | 存为 Inference（ai:reasoning） | ✅ source=consult，可信度 0.7 |
| 反思洞察"用户重视长期规划" | 存为 Hypothesis/Belief | ✅ ai:reflection / ai:belief，可回滚 |
| 用户说"笑死我了哈哈" | 不写入长期记忆 | ✅ Consent 拦截（joke≥0.7 且无实质信息） |

**发现的问题**：无。

**优化建议**：推理记忆尚无显式 hypothesis 状态位（用 reflection/contested 近似），若需强类型可加 kind 枚举。

# 2. 记忆纠错与版本记录

**测试方案**：制造新旧冲突，验证不覆盖、历史保留、认知变化追踪、回滚。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| "用户喜欢Python" → 纠正"现在用Java" | 旧记忆不删除，标记 superseded | ✅ supersede + valid_to + 历史保留 |
| 低可信旧事实被纠正 | 直接废弃 | ✅ 规则判定 update → superseded，新事实可信度升到 0.7 |
| 高可信/多次确认的旧事实被纠正 | 调查后保留 | ✅ keep 分支：不动置信度，记 investigate 审计 |
| 无法判断的纠正 | 降权 + 待核查标记 | ✅ conflict 降权 + status=contested |
| 每次变更 | 写入 memory_history | ✅ 旧值→新值、旧置信度→新置信度、原因 |
| 信念被修改 | 可回滚 | ✅ belief_log 版本 + rollback_belief |

**发现的问题**：纠正调查的 LLM 调用有 600s 全局节流，高频纠正时退化为规则判断（可接受，但规则在"多次确认"判定上依赖访问计数）。

**优化建议**：节流改为按 scope 而非全局；把"调查结果"也写入 feedback_log 的 weight，供后续 ML 学习调查决策。

# 3. 网络语言理解

**测试方案**：对"麻了 / 笑死 / 绷不住了 / 寄了 / 离谱 / 我要炸了"等做表达分析，验证不误判为真实情绪或事实。

**测试用例 / 预期 / 表现**：

| 输入 | 预期 | 实际表现 |
|---|---|---|
| 麻了 | 网络用语，无奈表达，非事实 | ✅ joke=0.3，情绪=轻度压力表达，多义意图 |
| 笑死 | 有趣(0.8)/嘲讽(0.15)，需上下文 | ✅ 双意图 + need_context |
| 绷不住了 | 搞笑/压力双义 | ✅ 双意图 + need_context |
| 寄了 | 完蛋了，非真实事件 | ✅ 本次测试发现词典缺失，**已补录** |
| 我要炸了 | 夸张表达，非真实情绪爆发 | ✅ joke=0.8，情绪=轻度压力表达 |

**发现的问题**：静态词典有滞后性（本次发现"寄了"缺失）；新梗无法自动学习。

**优化建议**：增加"未知网络词"节流式 LLM 学习（识别到未收录但高玩笑概率的词 → 入 language_context 待人工/自动收录）；词典按季度维护。

# 4. 语境理解

**测试方案**：同一表达在不同上下文下的含义验证。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| "离谱" 单独出现 | 标记需上下文（need_context） | ✅ need_context=true，多义意图 |
| 同一句话在轻松/严肃场景 | 结合用户表达画像判断 | 🟡 规则层只标记歧义，消歧交给 LLM；画像注入"用户常反讽，朋友式表达"辅助 |

**发现的问题**：无显式"结合上文消歧"的规则实现，完全依赖 LLM 上下文窗口。

**优化建议**：会话内歧义词消歧可缓存（同词上次判定结果），降低重复 LLM 成本；表达画像反讽度 ≥0.4 时优先按"调侃"解读。

# 5. 表达习惯学习

**测试方案**：连续消息更新表达画像，验证 slang/irony/emoji/formality 的滑动学习与适配注入。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| 连续 6 条带梗消息 | slang_frequency ≥0.4 | ✅ 0.469 |
| 反讽消息 | irony_usage 上升 | ✅ |
| 正式消息（合同/开会） | formality_level 上升 | ✅ |
| 画像成熟后 | 注入"【用户表达风格】…调整正式程度" | ✅ describe 非空 |

**发现的问题**：阈值（0.4/0.6）是拍脑袋定的，未经真实数据校准；画像只统计不展示给用户。

**优化建议**：跑数据后按用户分布校准阈值；`/我的风格` 命令让用户可查看/纠正画像。

# 6. 关系系统

**测试方案**：行为证据驱动关系状态累积，验证 trust/familiarity/closeness/stage 与时间衰减。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| 长期交流 | familiarity 每次 +0.02 | ✅ |
| 主动分享经历 | trust/familiarity/closeness 上升 | ✅ share 事件 |
| 用户纠正 | trust 下降 | ✅ dispute 事件 |

**发现的问题**：阶段阈值和单次增量未经真实数据验证；关系只影响 prompt 注入，无量化"称呼变化"。

**优化建议**：跑数后校准阈值；关系 stage 可直接驱动 persona 称呼字段。

# 7. 人格稳定性

**测试方案**：核心人格不可变、自适应可成长、防漂移。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| 用户纠正 AI 核心认知（"我才不是那样的人"） | 高可信核心记忆保留 | ✅ ai 命名空间规则保守：conf≥0.8 → keep |
| persona.md 修改后重启 | 核心字段重新同步 | ✅ 启动自动同步（16+ 字段） |
| 对话沉淀经历/信念 | 可成长、带可信度 | ✅ experience/belief/reflection |
| 人格类修改 | 触发人工审核 | ✅ audit review_required |

**发现的问题**：核心人设的"不可变"依赖 persona.md 重同步，若用户长时间不重启，core 字段可被对话中低置信度条目污染（已用 ai scope 保守规则缓解）。

**优化建议**：core 字段写入前强制走 HITL 审核（当前只有纠错路径触发），或在每次 grow 时校验 core 字段与 persona.md 一致性。

# 8. Reflection 反思机制

**测试方案**：验证从事件/关系/目标总结经验并影响未来行为。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| daily_reflect | 生成洞察写入 ai:reflection | ✅ 3 条内、带来源与可信度 |
| 信念审查 accept/revise/reject | 动作 + 版本日志 | ✅ reflect_beliefs |
| 洞察注入未来回复 | "我的经历与观点"块 | ✅ compose 注入 |

**发现的问题**：反思只写不改行为参数（人格/策略不随反思自动调整），闭环到"行为变化"这一步依赖 prompt 注入，间接生效。

**优化建议**：反思产出可驱动 relationship/policy 参数微调（经 HITL），形成显式行为回路。

# 9. Reasoning Memory

**测试方案**：事实与推理分离、来源、置信度。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| "用户学习 Agent 开发" | 事实（memories） | ✅ source=ingest |
| "用户喜欢研究底层架构" | 推理（ai:reasoning） | ✅ source=consult，置信度 0.7 |
| "用户可能准备进入 AI 行业" | 假设（reflection） | ✅ source=reflection，置信度 0.6 |
| 变更 | 可追踪/可回滚 | ✅ memory_history + belief_log |

**发现的问题**：推理与假设的区分靠 source 隐式表达，无显式类型字段。

**优化建议**：ai:reasoning 增加 kind 枚举（inference/hypothesis），检索时可按类型过滤。

# 10. Goal 系统

**测试方案**：目标管理避免固定计划表，支持动态调整。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| /目标 添加 | 入库（标题/优先级/状态） | ✅ |
| /目标列表 /目标完成 | 查询/完成 | ✅ |
| 决策顾问 | 一次一问、不生成计划表 | ✅ 最多 4 轮 → 下一步行动 |
| 目标变化 | 可更新进度/状态 | ✅ progress/status 更新 |

**发现的问题**：无 motivation/confidence 字段；无"暂停/放弃"状态（只有 active/done）；无按目标的 current state（技能/资源）。

**优化建议**：补 motivation/confidence；加 paused/abandoned 状态；目标挂 current state（skill/resource/limitation）。

# 11. Belief World Model

**测试方案**：外部世界认知的来源/时间/可信度/变化过程；纠正时形成候选认知而非覆盖。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| ai:belief 写入 | 来源 + 置信度 | ✅ |
| 用户纠正 AI 认知 | 形成候选而非覆盖 | ✅ uncertain → contested 待核查 / update → superseded 保留旧值 |
| 认知变化过程 | memory_history 全程记录 | ✅ |

**发现的问题**：contested 记忆会继续参与检索（软过滤保留），可能造成回复不一致，依赖"我记得好像…？"措辞兜底。

**优化建议**：contested 记忆检索时加"（待核实）"标注，或默认不进 prompt 只在 /我的记忆 可见。

# 12. 世界模型纠错

**测试方案**：用户输入 vs 模型知识 vs 外部信息冲突时的可信度判断与认知更新。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| 用户纠正（update） | 旧认知 superseded，新认知高可信 | ✅ |
| 用户纠正（keep） | 保留旧认知，记审计 | ✅ |
| 用户纠正（uncertain） | 降权 + contested | ✅ |
| 核心/AI 认知被改 | HITL 审核 | ✅ audit review_required |

**发现的问题**：调查 LLM 的 prompt 无外部信息源（模型知识即 LLM 自身），无法对照"外部信息"。

**优化建议**：若接入外部检索，调查 prompt 增加"外部证据"输入项。

# 13. Retrieval 系统

**测试方案**：多维融合（向量/词法/图谱/时间/关系/重要性）而非纯语义。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| retrieve_detailed | 返回 rrf/policy/confidence 分数分解 | ✅ 各维度独立可查 |
| 时间推理 | superseded 不召回 | ✅ |
| 目标注意力 | 活跃目标相关记忆加权 | ✅ +0.08 |
| 表达/关系 | 关系分、用户状态注入 prompt | ✅ |
| 6 路召回 | 词法/向量/图谱/结构化/Rules/议题 | ✅ 各算法独立候选 + RRF |

**发现的问题**：检索无显式"时间窗口加权"（仅排除 superseded）；低分记忆软过滤保留可能引入噪声。

**优化建议**：按查询 time_hint 对 valid_from 加权；观察低分记忆召回率，必要时收紧软过滤。

# 14. Memory Governance

**测试方案**：低可信/玩笑/临时/敏感信息的过滤与降权。

**测试用例 / 预期 / 表现**：

| 用例 | 预期 | 实际表现 |
|---|---|---|
| 玩笑低信息 | 不保存 | ✅ consent keep=false |
| 玩笑有信息 | 低可信短期 | ✅ conf≤0.45 |
| 敏感信息 | 加密 + 不进索引 | ✅ privacy≥0.8 |
| 历史记忆 | 不召回 | ✅ superseded 过滤 |
| 低可信 | 软置信度措辞 | ✅ "我记得好像…？"/"内部参考" |

**发现的问题**：无"临时信息到期自动清理"（如一次性抱怨），依赖遗忘策略兜底。

**优化建议**：给临时情绪类记忆打 mclass=short + 短半衰期，明确"一次性信息"策略。

# 15. AI 味检查

**说明**：以下各项属回复质感，需在真实 DeepSeek + QQ 环境人工验收（本报告给出检查清单与系统侧防呆机制）。

| 检查项 | 系统侧防呆机制 | 验收方法 |
|---|---|---|
| 固定模板回答 | 人设懒散毒舌 + 结构化人设字段 | 连续问 5 个不同类型问题，看句式是否雷同 |
| 过度总结 | 人设"不要长篇大论" + 简短风格 | 看回复长度与分段 |
| 完整计划表 | 决策顾问"一次一问 + 下一步行动"（禁止一年计划） | 问"我要不要换工作"，看是否只问一个问题 |
| 强行模拟情绪动作 | 人设自带"（打哈欠）"设定，非程序化 | 看情绪动作是否自然、是否每句都有 |
| 把用户的话转机械标签 | 表达画像只注入风格不贴标签 + 记忆注入自然措辞 | 看是否出现"根据您的偏好（网络用语频率0.7）"类输出 |
| 缺少自然交流感 | 衔接语/来源标注/关系分影响语气 | 连续对话 20 轮，主观评分 |

**发现的问题**：无法在离线环境自动判定；以上防呆机制均为结构保证，非语义保证。

**优化建议**：上线后建立"AI 味抽查集"（每类问题 10 个），每周人工评分，纳入 memory-eval 的附加维度。

# 16. 总结

## 达标结论

16 项能力中 **11 项达标、4 项基本达标、1 项（AI 味）待真实环境验收**。系统具备完整的"存→信→忘→成长"认知闭环，不是 RAG 包装。

## 需要修复/增强的问题清单（按优先级）

1. **P1**：Goal 补 motivation/confidence/暂停态/current state（v6 评审已列，仍未落地）
2. **P1**：contested 记忆的注入策略（加"待核实"标注或默认不注入）
3. **P2**：网络用语动态学习（未收录新词自动入候选）
4. **P2**：表达画像/关系阈值跑真实数据校准
5. **P2**：反思 → 行为参数闭环（经 HITL）
6. **P3**：AI 味抽查集 + 每周人工评分

- 测试发现并修复：网络用语词典缺"寄了"；纠错调查 prompt 花括号转义 bug；规则兜底方向性（用户自身 vs AI 认知）
