# Yuno 路线图与待办

> 原则：不推翻现有架构，在已有模块上做增量增强；每个阶段必须可评测、可回滚。

## 已具备（v2.5）

- 统一记忆 + 七路检索 + 贝叶斯可信度 + 分类遗忘
- 情绪 / 睡眠 / 日程 / 环境 / 分享 / 生活 / 空间世界层
- 认知架构标准化接口、程序记忆、目标意图
- 记忆轨迹五维评分与对话质量五维评分
- 评测基线、回归门禁、消融矩阵、成本归因
- PostgreSQL 生产后端 + SQLite 兼容
- Web 管理台：评测、评分、消融、诊断、数据导入导出、运维播报

## 短期（建议下一轮）

| 优先级 | 事项 | 验证方式 |
|---|---|---|
| P0 | 检索排序校准：用 `memory-index --tune` 调 nlist/nprobe，重排权重对照 `memory-eval` | MRR 提升且 recall 不退化 |
| P0 | 时间线排序修复：从 `time-eval` 的 timeline_order 失败样本构造探针 | timeline_order ≥ 0.75 |
| P0 | 评测集扩充：`memory-probes` 从新查询日志持续导出，badcase 回流 | probes ≥ 100 且指标可复现 |
| P1 | Web 接口级权限：只读可看不可跑，高风险操作仅 admin | 新增鉴权矩阵测试 |
| P1 | PG 连接池参数支持环境变量 | `config-validate` + PG 并发测试 |
| P1 | PG 故障自动告警 / 降级通知闭环 | `pg-guard` 演练 |
| P1 | ruff 忽略项清零，接入 mypy / pyright 门禁 | CI 通过 |

## 中期

- **检索自我评估**：检索前判断是否需要记忆；命中分数低时二次检索或含糊表达。
- **记忆整合器**：相似记忆自动合并、矛盾进失效队列、低价值记忆降权遗忘。
- **失败驱动反思**：把评测低分与用户纠正回流为 `procedures` 或 `ai:reflection`。
- **评测集建设**：记忆召回 / 防编造 / 人设一致 / 多轮一致 / 纠错，每维 50~100 条入 CI。
- **Docker Compose 部署**：app + PostgreSQL + pgvector 一键启动。
- **备份恢复自动化**：定时备份 + 恢复演练 + 失败播报。
- **多租户隔离**：基于 `scope_meta` 完善注册、权限、隔离与 Web 管理。
- **全文检索增强**：数据量增长后评估 PostgreSQL 原生全文检索 / `pg_bigm`。

## 长期

- **模型蒸馏**：情绪、提取、重排等高频 LLM 路径替换为本地小模型。
- **代码拆分**：`plugins/_db.py`、`plugins/_db_pg.py`、`tools.py` 继续收敛。
- **可观测性**：指标导出、请求级 trace 大盘、错误预算。
- **公网安全加固**：TLS、WAF、限流、密钥轮换、审计告警。
- **PostgreSQL 分区**：数据量极大时按 scope 分区。

## 验证纪律

- 每个阶段先落 baseline，再单变量调整，最后对比回归。
- SQLite 与 PostgreSQL 双后端都跑 `pytest tests/ -q`。
- 核心指标对照 `docs/baselines/ci_eval.json`，退化超过 0.05 不得合入。
- 新机制必须同时给出：开关、探针、评测命令、回滚方式。
